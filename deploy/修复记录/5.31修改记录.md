## 二、根因分析

### P-12 ~ P-14：详情页展示与部署链路

- 详情页组件 `antiqueDetail.vue` 原先为简单 `el-card` + 纯文本列表，视觉层次弱、留白不合理。
- 前端为 Vite 构建的静态 SPA，Nginx 直接托管 `/var/www/knowledge-service/dist/`，**修改 `.vue` 源码不会自动生效**，必须执行构建并覆盖部署目录。
- 用户访问的是 80 端口生产构建，而非 `npm run dev` 开发服务器。

### P-15：移动端布局异常

- 桌面端为对齐左右栏，引入了 `syncGalleryLayout()`，将左侧图片框 `min-height` 设为右侧信息区高度。
- 在 **≤768px 单栏布局** 下，右侧信息在图片**下方**，仍套用该逻辑会导致图片区域被撑得过高，出现大面积空白，看起来像「没有更新」或布局错乱。
- 原 `@media` 规则不完整，未重置 `min-height`、图片最大高度和按钮排列。

### P-16：移动端缓存

- SPA 入口 `index.html` 未设置 `Cache-Control`，部分手机浏览器会长期缓存旧壳文件，导致即使 `assets/` 已更新，仍加载旧版 JS 引用。

## 三、修改文件清单

### 前端（需 `npm run build` + 同步 `/var/www/knowledge-service/dist` + reload nginx）

| 文件 | 改动 |
|------|------|
| `myvue/src/views/antiqueDetail/antiqueDetail.vue` | **UI 重构**：面包屑、左图右文双栏、信息卡片、标签、评论区样式；主题色 `#8b4513` 与搜索结果页统一 |

| 同上 | **其他**：补注册 `v-clickoutside` 指令；图片 `@error` 重试；数据加载/图片加载后重新布局 |

## 四、部署步骤（本次实际执行）

```bash
cd "Overseas_cultural_relics_knowledge_service subsystem/myvue"

# 1) 构建
npm run build

# 2) 同步到 Nginx 站点目录
sudo cp -r dist/* /var/www/knowledge-service/dist/

# 3) 重载 Nginx（若更新了缓存配置）
sudo nginx -t && sudo systemctl reload nginx
```

## 五、验证方式

```bash
# 1) 确认线上入口指向新构建（hash 会变）
curl -s http://127.0.0.1/ | grep -o 'index-[^"]*\.js'

# 2) 确认 index.html 不缓存
curl -I http://127.0.0.1/index.html | grep -i cache-control

# 3) 详情页新样式关键字存在于构建产物
grep -l 'detail-page' /var/www/knowledge-service/dist/assets/antiqueDetail*
```

**浏览器 / 手机端：**

1. 从「关键字 / 分类 / 专业搜索」进入 **搜索结果**，点击文物卡片（路由 `/antiqueDetail?objectId=...`）。
2. 桌面端：左图 sticky、与右侧信息顶部/底部对齐。
3. 手机端：图片在上、信息在下；图片高度适中，无大块空白；收藏/外链按钮全宽。
4. 若仍见旧版，对详情页执行 **强制刷新**；iOS Safari 可尝试清除网站数据。

> 说明：从 **首页** 「查看详情」进入的是 `/relicDetail`（另一组件），本次未改；搜索链路才是 `/antiqueDetail`。
