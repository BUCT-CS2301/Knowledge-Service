## 二、根因分析

### P-23 ~ P-25：时间轴图片

- 原 mock 使用 `neeko-copilot.bytedance.net` 内网地址，前端 `imageFor()` 过滤后回退 SVG 占位图。
- 后续改用单一 `/timg.jpeg`，导致所有卡片图片相同。
- Wikimedia / Cleveland CDN 在当前网络环境不可达（HTTP 000 或超时）。

**方案**：策展数据与图片路径分离；图片放入 `public/timeline/`（构建后可通过 `/timeline/xxx.png` 访问），不依赖外网。

### P-24 / P-26：跳转与部署

- 旧版 `dist` 中 `showRelicDetail` 仅 `console.log`，未调用路由。
- Vite 生产构建需手动 `build` + 覆盖 Nginx 托管目录后才会生效。

### P-27 ~ P-28：知识图谱

- 节点点击仅切换左侧信息面板，未绑定路由跳转。
- 后端图谱节点未返回 Neo4j `object_id`，前端无法直达 `antiqueDetail`。
- 初版用 `@click` + 图谱坐标阈值区分拖拽，任意微小移动即 `nodeDragMoved=true`，真实轻点常被误判为拖拽（P-28）。
- 联调期间曾误删 `handleWheel`、重复定义 `handleNodeMouseDown`，已在源码中修复并重新部署。

**方案**：

1. 后端 Cypher 补充 `object_id`、`imageUrl` 写入 `GraphNode`。
2. 前端 `navigateFromNode()` 按节点类型跳转；`mousedown` 记录屏幕坐标，`mouseup` 判定是否跳转。
3. 拖拽阈值使用 **屏幕像素 12px**（`Math.hypot(screenDx, screenDy) > 12`），避免手抖误判。
4. 拖动后仅展示详情面板，可通过「查看详情 →」按钮作为备用入口。

### P-29：统计分析看板

- 可视化首页 `Index.vue` 有「统计分析看板」入口，链接为 `#/visualization/dashboard`。
- `router/index.js` 未注册该路由，Vue Router 无匹配组件，页面空白。

**方案**：在 `myvue/src/router/index.js` 增加懒加载路由，指向已有 `Dashboard.vue`。

### P-30 ~ P-31：收藏 / 评论不进后台管理

**收藏（P-30）**

- 首页 `IndexView.vue` 的「收藏」仅写入 `localStorage.collections`，未调用 `/search/searchById/collect`，MySQL `collect` 表无记录。
- 个人中心 `favourite.vue` 虽对接 `/user_admin/collect`，但用户多在首页操作，故后台列表为空。

**评论（P-31）**

- 评论写入 `comment_check` 成功，但 `CommentMapper.findByUid` 使用隐式 **INNER JOIN** `cultural_relics_data`。
- Neo4j 文物的 `relic_id` 为 `objectId.hashCode()`，不在 MySQL 文物表，查询结果被过滤为空。

**方案**：

1. 首页收藏/评论统一走后端 API（`collectRelic`、`/search/searchById/comment`）。
2. `CommentMapper.xml` 三处查询改为 `LEFT JOIN`，`relicname` 用 `COALESCE(cultural_relics_data.object_name, comment_check.relic_name, …)`。
3. `comment_check` 表增加 `relic_object_id`、`relic_name`；评论接口支持 `objectId` / `relicName`。
4. `relicDetail.vue` 收藏/评论改走后端（不再仅用 localStorage）。

### P-32：登出后收藏状态残留

- `MainHeader.off_log` 未清除 `localStorage.collections`、`comments`。
- 登出时先 `removeItem('username')` 再读 `username` 过滤 `users` 数组，逻辑顺序错误。
- `getCurrentUserId()` 曾回退读取 `objectId`，与文物 UUID 混用风险。

**方案**：

- 新增 `clearUserSession()`（`api/user.js`），登出与登录时统一清理会话与本地收藏/评论缓存。
- `getCurrentUserId()` 仅读 `username`（数字用户 ID）。

### P-33：首页评论弹窗不显示

- 项目使用 **Element Plus 2**，`IndexView` 弹窗仍写 Element UI 2 的 `:visible.sync`。
- 绑定无效，`detailVisible=true` 时对话框不渲染，用户只能进详情页评论。

**方案**：改为 `v-model="detailVisible"`，弹窗内增加多行输入与「发表评论」按钮；未登录点击评论时提示先登录。

### P-34：详情页无法展示社区评论

- 用户期望详情页「用户评论」区展示**所有用户**对该文物的评论（社区模式），而非仅自己可见或始终为空。
- **Neo4j 详情**（`detailByObjectId`）只返回文物属性，未附带 `commentView`，`antiqueDetail` 评论区一直为空。
- **relicDetail / 首页弹窗** 通过 `POST /search/searchById` 拉评论，该接口依赖 MySQL `cultural_relics_data` 中存在对应 `rid`；首页推荐文物（如 Cleveland `149146`）不在 MySQL 表内，接口失败，评论列表为空。
- 评论实际已写入 `comment_check`，但前端无独立「按文物查全部评论」的接口。

**方案**：

1. 后端新增 `POST /search/relicComments`，按 `rid` 或 `objectId`（hash 为 `relic_id`）调用 `viewcommentfrelics`，**不依赖** MySQL 文物表是否存在。
2. `detailByObjectId` 响应中增加 `commentView` 字段。
3. 前端 `getRelicComments()`（`api/relic.js`）统一加载评论；`antiqueDetail`、`relicDetail`、`IndexView` 发表成功后刷新列表（不再 `$router.go(0)`）。

### P-35：浏览页查询结果无真实图片

- 「浏览 → 朝代/材质/博物馆/用途 → 查询结果」卡片全部显示前端 SVG 占位图（「文物 · 示意图」），文字元数据正常。
- **不是 MySQL 故障**：`artifact` 表 7536 条，其中 **7110 条**有 `image_url`。
- **根因在 Neo4j**：分类接口 `POST /search/classification` 从 Neo4j 查文物；修复前返回 100 条结果 **`img_url` 全部为空**（`Artifact` 节点未写 `imageUrl`，也无 `展示图片` 关系）。
- 前端 `result.vue` → `getArtifactImageUrl()` 在无 URL 时生成 SVG 占位，属预期回退。

**方案**（数据修复，无需改业务代码）：

1. 运行 `museum/add_images_to_neo4j.py --allow-remote`，按 `accession_number` 将 MySQL 图片 URL 写入 Neo4j。
2. 为匹配节点设置 `a.imageUrl`，并 `MERGE (a)-[:展示图片]->(:Image {url})`。
3. 生产环境已执行一次：匹配 **3874** 节点，**3698** 条含展示图片；「唐」朝代抽样 **94/100** 条返回真实 `img_url`。

**复现命令**（Neo4j 数据丢失或重建后需重跑）：

```bash
cd "Overseas_cultural_relics_knowledge_service subsystem/museum"
.venv-sync/bin/python add_images_to_neo4j.py --allow-remote
```

### P-36：统计分析看板移除筛查控件

- 看板顶部有日期范围、博物馆下拉（如「卢浮宫」）与「刷新数据」按钮，但 `fetchDashboardData()` 从未读取 `dateRange` / `selectedMuseum`，筛查对数据无实际过滤效果，界面冗余。
- 用户要求统计分析板块不再展示该筛查区域。

**方案**：删除 `Dashboard.vue` 中 `dashboard-controls` 区块及相关状态（`dateRange`、`selectedMuseum`、`isLoading`、`refreshData`）；页面 `onMounted` 仍自动请求 `/api/v1/data/dashboard`，失败时回退 mock 数据。

## 七、知识图谱跳转规则

| 节点类型 | 轻点（未拖动） | 拖动后 |
|---------|---------------|--------|
| 文物 🏺 | 有 `objectId` → `/antiqueDetail?objectId=...`；否则 → `/relicDetail?from=kg&name=...`（经 `sessionStorage.graphRelicDetail`） | 显示左侧面板，点「查看详情 →」跳转 |
| 博物馆 🏛 | `/museumDetail?id={node.id}&name={node.label}` | 同上 |

**交互实现要点**（`KnowledgeGraph.vue`）：

- 节点 `circle` 绑定 `@mousedown.stop="handleNodeMouseDown"`，SVG 绑定 `@mouseup="handleMouseUp"`。
- `nodeDragStart` 同时记录图谱坐标（`mouseX/Y`）与屏幕坐标（`screenX/Y`）。
- `handleMouseMove` 中用屏幕位移判定 `nodeDragMoved`（阈值 12px），图谱坐标仅用于更新节点位置。
- 调试插桩已于修复确认后移除，生产 bundle 无调试 `fetch` 调用。

## 九、社区评论数据流（P-34）

```
用户发表评论
  → POST /search/searchById/comment { uid, rid, content, objectId?, relicName? }
  → 写入 comment_check（relic_id = hashCode(objectId) 或数字 rid）

详情页 / 弹窗加载评论
  → POST /search/relicComments { rid } 或 { objectId }
  → CommentMapper.findByRid（LEFT JOIN user，不依赖 cultural_relics_data）
  → 返回全部用户的 CommentView 列表

Neo4j 文物详情首屏
  → POST /search/detailByObjectId
  → 响应 data.commentView 同上
```

**说明**：「我的评论」（个人中心）仍走 `/user_admin/comment`，按用户维度筛选；详情页走 `/search/relicComments`，按文物维度展示社区评论。

## 十、浏览页图片数据流（P-35）

```
MySQL artifact（accession_number + image_url）
  → add_images_to_neo4j.py 按馆藏编号匹配
  → Neo4j Artifact.imageUrl + (:Artifact)-[:展示图片]->(:Image)

前端「浏览 → 分类 → 查询结果」
  → POST /search/classification
  → Neo4jArtifactSearchService（Cypher 读 imageUrl / 展示图片）
  → result.vue imageFor(item) → 外链经 normalizeExternalImageUrl 代理
```

**说明**：P-09（5.30）曾解决过类似问题；若 Neo4j 重新导入未带图片属性，需再次运行补图脚本，**不是 MySQL 库损坏**。
