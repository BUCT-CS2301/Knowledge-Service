### 5.2 `import_to_neo4j.py` 安全优化

**原风险：** 脚本开头 `MATCH (n) DETACH DELETE n` 会清空全部节点；配置曾指向远程 IP，误跑将导致 6 万+ 数据丢失。

**优化措施：**

| 策略 | 说明 |
|------|------|
| 默认连本地 | `NEO4J_URI` 默认 `bolt://127.0.0.1:7687` |
| 禁止远程清空 | 远程需 `--allow-remote`，且永远禁止 `--wipe` |
| 默认增量同步 | 使用 `MERGE`，不再默认删库 |
| 清空需双确认 | 仅本地：`--wipe --i-understand-delete-all` |
| 支持 `--dry-run` | 只预览不写库 |

**禁止操作：**

```bash
# 不要对远程库执行
NEO4J_URI=bolt://39.106.231.119:7687 python import_to_neo4j.py
```

### 5.3 登录 / 注册修复

**登录问题根因：**

- 前端调用 `/api/v1/auth/login`（不存在，404）
- 失败后回退 `localStorage` 本地用户，导致 1001/123456 无法登录

**修复：**

- 登录：`POST /users/login`，body `{"username":"1001","password":"123456"}`
- 注册：`POST /users/register`，写入本地 MySQL `user` 表
- 注册成功后使用系统分配的**数字用户 ID** 登录

**用户数据存储：**

| 功能 | 存储位置 |
|------|----------|
| 注册 / 登录 | 本地 MySQL `muse.user` |
| 收藏 / 评论 | 本地 MySQL 相关表 |
| 文物搜索（现） | 远程 Neo4j |

## 十、查询结果图片与知识图谱演示模式（2026-05-28 追加）

### 10.1 问题描述（用户反馈要点）

1. **查询结果页**：提示「当前为演示数据（后端未连接）」及 `Request failed with status code 500`；卡片标题为青铜方鼎、青花瓷瓶等，配图却是 picsum 随机风景/街景，与文物名明显不符。
2. **知识图谱页**：节点极其密集，相同绿色圆圈+棕色图标，标签重叠不可读；希望只展示部分数据做演示，不要一次加载全库。

### 10.2 根因分析

#### 图片

| 现象 | 根因 |
|------|------|
| 标题与图片不符 | 后端失败时前端回退 `MOCK_ARTIFACTS`，`img_url` 使用 `picsum.photos` 随机图；无图时 `result.vue` 也用同一 picsum 占位 |
| 远程库是否有图 | 远程 Neo4j 有 `Image` 节点（约 6575），搜索 Cypher 通过 `展示图片→Image.url` 取图；实测关键字「瓷」命中结果 **`img_url` 多为空**（无关系或 `unknown`），并非「库里有图但前端没用」 |
| 500 / 演示数据 | 历史原因含 `UnsupportedOperationException`（不可变列表，已在 5.5 修复）；接口失败仍会走 mock。连接正常时不应再出现 500 |
| 结果条数异常 | `OPTIONAL MATCH` 多关系产生笛卡尔积，100 条结果仅 13 个 `object_id` |

#### 知识图谱

| 现象 | 根因 |
|------|------|
| 节点过密 | `KnowledgeGraphServiceImpl` 对文物 `limit=30`，但 **`periodRepository.findAll()` 加载全部 1034 个朝代**，再加 6 个博物馆，合计约 1070 节点 |
| 样式单一 | 前端 SVG 节点类型渐变未区分时，大量节点重叠；随机坐标加剧不可读 |

### 10.3 修改说明

#### 图片

- 新增 `artifactPlaceholder.js`：按材质/品类/名称关键词生成 **SVG 示意图**（青铜/陶瓷/玉器/书画等配色），不再使用 picsum。
- `mockArtifacts.js`：演示数据改为中文元数据、`img_url` 留空，由占位逻辑统一渲染。
- `result.vue`：通过 `getArtifactImageUrl()` 展示真实 URL 或类型占位图。
- `Neo4jArtifactSearchService.java`：`WITH collect(DISTINCT …)` 聚合后再 `RETURN`，并按 `object_id` 去重，消除重复行。

#### 知识图谱

- 重写 `KnowledgeGraphServiceImpl`：单条 Cypher 只取 **LIMIT 件文物** 及其关联博物馆、朝代（默认 25，最大 40），不再 `findAll()` 朝代。
- 节点主键使用 `elementId(a)`，避免 `object_id` 重复导致只显示 4 个文物节点。
- `KnowledgeGraphController`：默认 `limit=25`。
- `KnowledgeGraph.vue`：环形分层布局、标签截断、默认 `limit=25`、本地 JSON 最多 40 节点兜底。

## 十一、分类/关键词浏览 500 与误显示演示数据（2026-05-28 追加）

### 11.1 问题描述

用户点击搜索、按材质/朝代/品类分类浏览（如「陶瓷」）时，结果页出现：

- 浏览器/控制台：`Request failed with status code 500`
- Toast：「无法连接后端，已加载演示数据」
- 横幅：「当前为演示数据（后端未连接）」

示例 URL：`/fore/result#/result?mode=classify&c=mart&v_2=陶瓷`  
说明：`c=mart` 为**材质（material）分类**的约定参数，不是 `smart` 拼写错误。

### 11.2 复现与日志

```bash
# 模糊搜索正常
curl -X POST http://127.0.0.1:8085/search/obscure \
  -H 'Content-Type: application/json' -d '{"keyword":"瓷"}'
# → HTTP 200, state=200

# 材质/朝代/品类分类均 500
curl -X POST http://127.0.0.1:8085/search/classification \
  -H 'Content-Type: application/json' -d '{"c":"mart","v_2":"陶瓷"}'
# → HTTP 500

# 博物馆分类正常（走独立 Cypher 路径）
curl -X POST http://127.0.0.1:8085/search/classification \
  -H 'Content-Type: application/json' -d '{"c":"museum","v_4":"克利夫兰"}'
# → HTTP 200
```

`journalctl -u knowledge-service` 关键报错：

```
Invalid input 'WHEREmat': ... SyntaxError
"WHEREmat.name CONTAINS $kw"
```

### 11.3 根因

| 现象 | 根因 |
|------|------|
| 材质/朝代/品类分类 500 | `Neo4jArtifactSearchService.searchByRelatedNode()` 使用 Java text block 与 `+` 拼接 Cypher 时，`WHERE` 与变量名粘连为 `WHEREmat` / `WHEREp` 等，Neo4j 语法错误 |
| 博物馆分类正常 | `searchByMuseum()` 为独立拼接，未触发该 bug |
| 模糊搜索有时正常 | `searchByKeyword()` 未走 `searchByRelatedNode` |
| 前端误显示演示数据 | axios 收到 HTTP 500 进入 `result.vue` catch，加载 `MOCK_ARTIFACTS`；与真实「后端未连接」无关 |
| 无结果也可能误演示 | 历史 `requireNonEmpty` 抛 `ProductNotFoundException`（state=4000），前端未按空列表处理 |

### 11.4 修改说明

1. **后端**：`searchByRelatedNode` 改为普通字符串拼接，显式 `\nWHERE ` 分隔，避免 `WHEREmat`。
2. **后端**：`CartServiceImpl.requireNonEmpty` 对空结果返回空列表，不再抛异常导致 500/4000 歧义。
3. **前端**：`parseSearchResponse` 对 `state=4000` 按空列表处理，避免误走 mock。
