## 二、根因分析

### P-09 / P-08：搜索与详情的数据-图片错位
- 搜索读取的是**远程 Neo4j 图谱**（中文翻译版，UUID 主键，`imageUrl` 全空、无 `展示图片` 关系）。
- 补充的 `data.csv` 已进**本地 MySQL**（英文、数字主键、含 7110 条真实图片 URL），但与 Neo4j 节点**主键对不上**（数字 vs UUID，标题中英不一致），所以往 MySQL 加图片对搜索结果零影响。
- 详情页 `antiqueDetail.vue` 同时存在三处问题：请求地址写死 `http://localhost:8080`（应为同域 / 8085）、后端 `searchById` 按 **MySQL 数字 id** 查（与 Neo4j 的 hashCode 伪 id 不匹配）、字段名/`href` 拼写错误。

> 关键桥梁：Neo4j 的 `Artifact` 节点保留了 `accession_number`（馆藏编号），与 MySQL 的 `accession_number` 一致，匹配率约 **6717~7140 / 7510（89%~95%）**，据此在**保留中文翻译**前提下补齐图片与原地址。

### P-10：时间轴
- 前端 `/api/v1/data/timeline` 判断用 `response.data.code`，后端返回 `state`，恒回退到写死 mock；mock 图片地址 `neeko-copilot.bytedance.net` 为内网地址，外网无法加载。
