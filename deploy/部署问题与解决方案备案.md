## 1. 部署架构概览

### 1.1 目标架构

```
浏览器
  │
  ▼
Nginx (:80)
  ├── 静态文件  → /var/www/knowledge-service/dist
  └── 反向代理  → Spring Boot (:8085)
                      ├── MySQL (:3306)  业务数据 + artifact/museum
                      └── Neo4j (:7687)  知识图谱可视化
```

### 1.2 最终采用方案

| 组件 | 方案 | 说明 |
|------|------|------|
| 前端 | 预构建 `dist` + Nginx 托管 | 无需在服务器上 `npm run build`（已有产物） |
| 后端 | systemd 托管 JAR | 服务名 `knowledge-service` |
| MySQL | 本地 `mysql-server` | 替代不可用的阿里云 RDS |
| Neo4j | 本地 `apt install neo4j` | 替代不可用的 Neo4j Aura；Docker 拉镜像失败 |
| 知识图谱构建 | `run_kgc.py` + `import_to_neo4j.py` | Morph-KGC 有回退逻辑；Neo4j 同步用独立脚本 |

### 1.3 与原项目配置的差异

原 `application.yml` 指向：

- MySQL：`rm-2zewpqd4a1y90c2uujo.mysql.rds.aliyuncs.com`
- Neo4j Aura：`neo4j+s://0e2544eb.databases.neo4j.io:7687`

**上述远程地址在本次部署环境中均无法 DNS 解析（NXDOMAIN）**，已改为本地数据库。

## 3. 环境与依赖问题

### P-01：服务器缺少运行环境

**现象**

```text
Command 'java' not found
Command 'mvn' not found
Command 'nginx' not found
Command 'npm' not found
```

**原因**：全新 Ubuntu 服务器，未预装项目依赖。

**解决方案**

```bash
sudo apt-get update
sudo apt-get install -y openjdk-21-jdk maven nginx npm mysql-server docker.io
```

**验证**

```bash
java -version    # openjdk 21
mvn -version     # Maven 3.8+
nginx -v
npm -v
```

**备案**：后续新机器部署时，优先执行 `deploy/SERVER-DEPLOY.md` 第 2 节环境检查清单。

### P-02：后端 JAR 未编译

**现象**：`museum/target/` 目录不存在，systemd 无法启动后端。

**解决方案**

```bash
cd "Overseas_cultural_relics_knowledge_service subsystem/museum"
mvn -q -DskipTests package
# 产物：target/demo-0.0.1-SNAPSHOT.jar
```

**备案**：每次拉取代码或修改后端 Java 代码后需重新 `mvn package` 并 `systemctl restart knowledge-service`。

## 4. 后端 Spring Boot 问题

### P-03：SLF4J 与 Logback 冲突

**现象**

```text
LoggerFactory is not a Logback LoggerContext but Logback is on the classpath.
Either remove Logback or the competing implementation (class org.slf4j.helpers.NOPLoggerFactory
loaded from ... slf4j-api-1.7.25.jar)
```

**原因**：`pom.xml` 中显式引入了旧版 `slf4j-api 1.7.25`、`log4j 1.2.17`，与 Spring Boot 3.2 自带 Logback 冲突。

**解决方案**

从 `museum/pom.xml` 删除以下依赖：

- `log4j:log4j:1.2.17`
- `org.slf4j:slf4j-api:1.7.25`
- `org.slf4j:slf4j-log4j12:1.7.25`

**修改文件**：`museum/pom.xml`

---

### P-04：MyBatis 与 Spring Boot 3 不兼容

**现象**

```text
Property 'sqlSessionFactory' or 'sqlSessionTemplate' are required
```

**原因**：`mybatis-spring-boot-starter` 版本为 `2.1.2`，不支持 Spring Boot 3 / Jakarta EE。

**解决方案**

```xml
<dependency>
    <groupId>org.mybatis.spring.boot</groupId>
    <artifactId>mybatis-spring-boot-starter</artifactId>
    <version>3.0.3</version>
</dependency>
```

**修改文件**：`museum/pom.xml`

---

### P-05：Neo4j Repository 未扫描

**现象**

```text
No qualifying bean of type 'com.repository.RelicRepository' available
```

**原因**：`DemoApplication.java` 已 import `@EnableNeo4jRepositories` 但未加注解。

**解决方案**

```java
@EnableNeo4jRepositories("com.repository")
public class DemoApplication { ... }
```

**修改文件**：`museum/src/main/java/com/DemoApplication.java`

---

### P-06：Neo4j 实体注解混用（OGM vs Spring Data Neo4j）

**现象**

```text
Cannot resolve reference to bean 'neo4jTemplate' while setting bean property 'neo4jOperations'
```

**原因**：

- 实体类使用 `org.neo4j.ogm.annotation.*`（旧 OGM 注解）
- Repository 使用 `org.springframework.data.neo4j.repository.Neo4jRepository`（Spring Data Neo4j 7）
- `pom.xml` 同时存在 `neo4j-ogm-embedded-driver 3.0.2` 与 `neo4j-java-driver 1.6.3`

**解决方案**

1. 删除 `pom.xml` 中旧版 OGM / driver 依赖，仅保留 `spring-boot-starter-data-neo4j`
2. 将实体类注解迁移为 Spring Data Neo4j 7：

```java
import org.springframework.data.neo4j.core.schema.Node;
import org.springframework.data.neo4j.core.schema.Id;
import org.springframework.data.neo4j.core.schema.GeneratedValue;

@Node("Relic")
public class RelicNode {
    @Id @GeneratedValue
    private Long id;
    // ...
}
```

**修改文件**：

- `museum/pom.xml`
- `museum/src/main/java/com/entity/RelicNode.java`
- `museum/src/main/java/com/entity/MuseumNode.java`
- `museum/src/main/java/com/entity/PeriodNode.java`
- `museum/src/main/java/com/entity/RelicRelation.java`
- `museum/src/main/java/com/entity/Product_neo4j.java`

## 5. 数据库连接问题

### P-09：远程 MySQL RDS 不可用

**现象**

```bash
getent hosts rm-2zewpqd4a1y90c2uujo.mysql.rds.aliyuncs.com
# Name or service not known
```

**原因**：RDS 实例可能已释放、过期或不在当前网络白名单；域名已失效。

**解决方案（本地 MySQL）**

```bash
# 1. 安装并启动
sudo apt-get install -y mysql-server
sudo systemctl enable --now mysql

# 2. 创建库与用户
sudo mysql -e "
  CREATE DATABASE IF NOT EXISTS muse;
  CREATE USER IF NOT EXISTS 'knowledge'@'localhost' IDENTIFIED BY 'knowledge123';
  GRANT ALL PRIVILEGES ON muse.* TO 'knowledge'@'localhost';
  FLUSH PRIVILEGES;
"

# 3. 导入初始化脚本
sudo mysql muse < deploy/database/init.sql
```

**配置变更**（`application.yml`）：

```yaml
spring:
  datasource:
    url: jdbc:mysql://127.0.0.1:3306/muse?serverTimezone=Asia/Shanghai&characterEncoding=UTF-8&useSSL=false&allowPublicKeyRetrieval=true
    username: knowledge
    password: knowledge123
```

**备案**：

- 初始化脚本路径：`deploy/database/init.sql`
- 若恢复使用云 RDS，需同步修改 `application.yml` 并确保安全组放行服务器 IP
- 生产环境密码应通过环境变量注入，勿写死在配置文件中

### P-10：远程 Neo4j Aura 不可用

**现象**

```text
java.net.UnknownHostException: 0e2544eb.databases.neo4j.io
```

**原因**：Aura 免费实例过期或已删除，域名 NXDOMAIN。

**尝试方案 A：Docker 部署 Neo4j**

```bash
docker run -d --name cultural_relics_neo4j \
  -p 7474:7474 -p 7687:7687 \
  -e NEO4J_AUTH=neo4j/knowledge123 neo4j:4.4
```

**失败原因**：服务器访问 `registry-1.docker.io` 超时（网络限制）。

**最终方案 B：apt 安装 Neo4j Community**

```bash
curl -fsSL https://debian.neo4j.com/neotechnology.gpg.key | \
  sudo gpg --dearmor -o /usr/share/keyrings/neo4j.gpg
echo "deb [signed-by=/usr/share/keyrings/neo4j.gpg] https://debian.neo4j.com stable 5" | \
  sudo tee /etc/apt/sources.list.d/neo4j.list
sudo apt-get update && sudo apt-get install -y neo4j
sudo neo4j-admin dbms set-initial-password knowledge123
sudo systemctl enable --now neo4j
```

**配置变更**（`application.yml`）：

```yaml
spring:
  neo4j:
    uri: bolt://127.0.0.1:7687
    authentication:
      username: neo4j
      password: knowledge123
```

**数据同步脚本**：

```bash
cd 知识图谱
source .venv/bin/activate
python import_to_neo4j.py
```

## 6. 前端与 Nginx 问题

### P-17：前端未部署、Nginx 仍为默认页

**解决方案**

```bash

sudo mkdir -p /var/www/knowledge-service/dist
sudo cp -r "Overseas_cultural_relics_knowledge_service subsystem/myvue/dist/"* \
  /var/www/knowledge-service/dist/

# 2. 配置 Nginx（/etc/nginx/sites-available/knowledge-service）
#    - root → /var/www/knowledge-service/dist

sudo rm -f /etc/nginx/sites-enabled/default

  /etc/nginx/sites-enabled/knowledge-service
sudo nginx -t && sudo systemctl reload nginx
```

**现象**


**原因**：原文件 LogicalSource 定义末尾多了非法 `]`，且 RelicSource 匿名节点与 `#RelicSource` 引用不一致。

**解决方案**：重写 RML 文件，修正 TTL 语法；后续又简化为 SQL 字符串形式的 logicalSource。

**修改文件**：`知识图谱/mapping.rml.ttl`

### P-22：Morph-KGC 产出 0 条三元组 ⚠️ 已绕过

**现象**

```text
INFO | Number of triples generated in total: 0.
```

**原因分析（待进一步排查）**：

- 原 RML 使用 `rml:connection "mysql_db"` + `RelationalModel` 写法，与 Morph-KGC 2.10 的 `[DataSource1]` 配置段可能不匹配
- 已尝试 `[DataSource1]`、SQL 字符串 source、简化 TriplesMap，仍为 0 条

**效果**：`python run_kgc.py` 可完整跑通 README 流程（构建 RDF → 样例查询 → 导出 neo4j_nodes.csv / neo4j_rels.csv）。

## 8. 业务代码与 API 问题

### P-12：演示账号登录失败

**现象**：POST `/users/login` 返回 `state: 6000, message: 密码错误`。

**原因**：

- `UserServiceImpl` 使用 MD5 三重加盐（salt=`museum`）存储密码
- `init.sql` 初始写入明文 `123456`

**解决方案**

1. 计算 MD5 哈希：`4DAA5D32203F6C48E54DC0FC51C64D3C`
2. 更新 `init.sql` 与数据库：

```sql
UPDATE user SET user_password='4DAA5D32203F6C48E54DC0FC51C64D3C' WHERE user_id=1001;
```

**演示账号**：用户 ID `1001`，密码 `123456`，用户名 `demo`

---

### P-13：CommentMapper 表名不一致

**现象**：评论插入可能失败或查询不到数据。

**原因**：`insert` 写入 `comment` 表，但 `select` 查询 `comment_check` 表。

**解决方案**：统一为 `comment_check`。

**修改文件**：`museum/src/main/resources/com/mapper/CommentMapper.xml`

---

### P-14：CartMapper 模糊搜索 SQL 语法错误

**现象**：`/search/obscure` 接口异常。

**原因**：`obscureSearch` 的 SQL 中存在重复占位符：

```sql
... or cat3 REGEXP #{str}  #{str} or makers_name ...
--                              ^^^^^ 多余
-- LIMIT 400,100 偏移过大，小数据集查不到结果
```

**解决方案**

- 删除多余 `#{str}`
- 改为 `LIMIT 0,100`

**修改文件**：`museum/src/main/resources/com/mapper/CartMapper.xml`

---

### P-15：可视化接口 Neo4j 失败时返回 500

**现象**：`/api/v1/data/dashboard`、`/timeline` 在 Neo4j 不可用时直接 500。

**原因**：`DashboardServiceImpl`、`TimelineServiceImpl`、`GeoMapServiceImpl` 未捕获 Neo4j 异常；`KnowledgeGraphServiceImpl` 已有 try-catch 降级。

**解决方案**

- Dashboard：Neo4j 查询包在 try-catch 中，失败时使用内置统计数据
- Timeline / GeoMap：失败时返回示例/mock 数据

**修改文件**：

- `museum/src/main/java/com/service/Impl/DashboardServiceImpl.java`
- `museum/src/main/java/com/service/Impl/TimelineServiceImpl.java`
- `museum/src/main/java/com/service/Impl/GeoMapServiceImpl.java`

### P-16：GeoMap 博物馆坐标缺失

### 10.3 敏感信息泄露风险

**现状**：原 `application.yml`、`run_kgc.py`、`知识图谱/README.md` 中含明文数据库/Neo4j 密码；若仓库公开，存在安全风险。

**建议方案**

1. **立即轮换**已泄露的所有云数据库密码（即使实例已失效）
2. 使用环境变量或 `application-prod.yml`（加入 `.gitignore`）：

```yaml
spring:
  datasource:
    password: ${MYSQL_PASSWORD}
  neo4j:
    authentication:
      password: ${NEO4J_PASSWORD}
```

3. systemd 中注入：

```ini
Environment=MYSQL_PASSWORD=xxx
Environment=NEO4J_PASSWORD=xxx
```

4. 从 Git 历史中清除敏感信息（`git filter-repo` 或 BFG）

**优先级**：高

**临时备案**：生产构建 RDF 可继续使用 `build_graph_from_mysql()` 回退；Neo4j 可视化数据以 `import_to_neo4j.py` 为准。
