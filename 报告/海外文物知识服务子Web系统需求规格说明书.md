# 海外文物知识服务子Web系统需求规格说明书

## 一、引言

### 1.1 项目背景

文物是历史文化传承的重要载体，当前海量海外文物信息缺乏统一、可视化、智能化的线上服务平台，文物研究人员、文化爱好者及普通用户存在文物资料查询繁琐、关联信息零散、数据缺乏直观展示、无个性化账号服务等痛点。为整合结构化海外文物信息，降低文物资料查阅与研究门槛，助力中华文物文化传播与学术研究参考，特研发海外文物知识服务子Web系统。

### 1.2 项目目标

依托知识图谱技术构建前端网页服务系统，打造集文物浏览、多模式检索、数据可视化分析、个人账号互动于一体的一站式文物知识服务平台。实现文物信息便捷查阅、多维精准检索、关联关系可视化呈现、用户个性化管理，保障系统高性能、高兼容、高安全、易维护，为不同层级用户提供流畅、专业的文物知识服务。

### 1.3 文档目的

本需求规格说明书明确系统功能需求、非功能需求、数据需求、接口需求、部署测试需求等全部业务与技术要求，作为系统设计、开发、测试、部署及后期维护的基准依据，统一开发与业务认知标准。

### 1.4 定义与缩写

知识图谱：以文物、博物馆、历史人物、朝代为实体节点，实体间关联关系为边构成的语义网络，存储展示文物关联信息

Vue3：轻量化前端开发框架，用于搭建页面结构与业务逻辑

Vite：前端项目构建工具，负责项目编译、打包与本地调试

Element Plus：Vue3适配桌面端UI组件库，统一页面视觉与基础交互

ECharts：数据可视化工具，实现时间轴、统计图表绘制

AntV G6：专业图可视化引擎，用于知识图谱关系渲染

Axios：网络请求工具，实现前后端数据交互

Pinia：全局状态管理工具，管控用户、列表、筛选等全局数据

Vue Router：路由管理工具，实现页面跳转、权限控制与懒加载

CSV/JSON：通用数据格式，用于检索结果导出与程序数据传输

### 1.5 适用范围

本文档适用于海外文物知识服务子Web系统前端网页端的设计、开发、测试、部署、运维全过程；覆盖文物浏览、数据查询、可视化展示、用户个人管理四大核心业务模块及接口、数据、性能、安全等配套需求。

## 二、总体概述

### 2.1 用户分类

1. 普通浏览用户（游客）：仅需公开文物信息浏览、基础查看功能，无收藏、评论、导出等权限；
2. 文化爱好者：使用检索、可视化分析、文物收藏、评论互动、数据导出等全部功能；
3. 文物研究人员：依赖高级组合检索、知识图谱语义检索、统计看板、数据导出、文物对比等专业功能。

### 2.2 系统架构需求

系统采用前后端分离B/S架构，自上而下分为三层：

1. 页面视图层：基于UI组件搭建所有功能页面，承载用户操作，展示文物数据与可视化图形；
2. 业务逻辑层：按功能模块拆分业务逻辑，处理视图切换、条件筛选、检索校验、图形渲染、用户行为管控，通过Pinia统一管理全局数据；
3. 数据交互层：封装网络请求，向后端发起数据请求，解析响应数据并向上层传递。

### 2.3 技术选型约束

前端必须采用Vue3+Vite为基础框架，UI组件使用Element Plus；常规可视化采用ECharts，知识图谱采用AntV G6；网络请求使用Axios，状态管理使用Pinia，路由管理使用Vue Router。

## 三、功能需求

### 3.1 数据浏览模块

1. 文物列表与详情查看：分页展示文物基础信息，点击条目进入详情页，展示文物简介、高清图片、结构化属性、关联实体；支持图片缩放、全屏查看，关联实体可跳转对应页面；
2. 相关文物推荐：按题材、朝代、人物、图像特征自动推送相似关联文物；
3. 文物对比：支持多件文物选中对比，直观展示属性与特征差异；
4. 组件化拆分：独立封装视图切换、条件筛选、详情展示、相关推荐、文物对比组件。

### 3.2 数据查询模块

1. 简易检索：页面顶部搜索框支持关键词模糊检索（文物名、场馆名、年代），结果分页展示，支持结果二次筛选；
2. 高级检索：独立检索页面，可自定义文物类别、年代区间、材质、收藏地点等多条件组合，实现精准定向查询；
3. 知识图谱语义检索：支持自然语言语句查询、实体+关系结构化指令查询；同步展示关系图谱与文物条目；

### 3.3 数据可视化模块

1. 知识图谱可视化：采用力导向布局，文物/场馆/朝代/人物为节点，关联关系为连线；支持缩放、拖拽、节点延伸、悬停查看属性；
2. 文物时间轴：按历史朝代时序排布，展示各时期文物数量；支持时间范围筛选、时间节点跳转对应文物列表；
3. 地理分布可视化：以地图为底图，标注博物馆地理位置，按藏品数量区分点位样式；支持查看场馆信息与馆藏文物清单；
4. 统计分析看板：展示文物总量、品类占比、朝代分布、馆藏排行等图表；支持图表联动筛选、页面截图保存；
5. 独立渲染组件：拆分图谱、时间轴、地理标注、统计看板专属渲染组件，交互逻辑独立封装。

### 3.4 用户个人信息管理模块

1. 账号管理：支持用户注册、密码登录、个人资料编辑；划分游客/登录用户权限，游客仅可浏览公开内容；
2. 收藏管理：支持文物加入收藏，可调整、删除收藏藏品；

## 四、接口需求

### 4.1 文物基础数据接口

1. 分页获取文物列表，支持页码、条数、类别、年代、场馆、排序规则传参；
2. 根据文物唯一编号获取单件文物完整详情（文字、图片、属性、关联实体）；
3. 推送同类型、同朝代、同题材相关文物数据。

### 4.2 数据查询接口

1. 关键词全文模糊检索接口；
2. 多条件高级组合检索接口；
3. 自然语言/结构化图谱语义检索接口；
4. 检索结果文件生成与前端下载导出接口。

### 4.3 可视化数据接口

1. 知识图谱实体节点、关联关系数据接口；
2. 时间轴历史时段、文物数量数据接口；
3. 博物馆地理位置、经纬度、馆藏数量接口；
4. 文物总量、品类占比、朝代分布、场馆排行等统计数据接口。

### 4.4 用户服务接口

1. 注册信息校验、登录验证、用户资料返回接口；
2. 浏览记录查询、删除接口；
3. 收藏添加、移除调整接口；

## 五、数据需求

### 5.1 前端基础数据结构

1. 文物基础数据：唯一编号、名称、品类、年代、材质、简介、图片地址、结构化属性、关联文物编号、更新时间；关联博物馆编号、名称、地区、经纬度、馆藏总数；
2. 用户个人数据：账号编号、登录名、邮箱、头像、创建时间；收藏分组信息、分组藏品列表、浏览记录；
3. 可视化专用数据：图谱实体与关系数据、时间轴时段与数量数据、地理坐标与馆藏数据、统计占比与数量数据。

### 5.2 全局状态管理需求

1. 文物状态模块：存储文物列表、详情信息、筛选排序条件、加载状态、数据总数，提供数据请求与条件更新方法；
2. 用户状态模块：存储登录信息、登录状态、身份凭证，封装登录、登出、资料修改逻辑；
3. 可视化状态模块：存储图谱、时间轴、地理分布、统计看板数据，提供数据调取与刷新方法；
4. 所有状态模块化隔离，独立管理、按需调用，避免数据冲突。

## 六、非功能需求

### 6.1 性能需求

1. 页面首屏加载耗时≤3秒；
2. 文物列表分页加载，接口响应迅速，大批量可视化数据加载流畅；
3. 对详情、图谱高频数据做本地缓存，减少重复请求；
4. 页面组件、图片资源采用懒加载，降低首屏加载压力。

### 6.2 兼容性需求

1. 兼容主流最新版电脑浏览器；
2. 采用自适应布局，适配电脑大屏、平板中等屏幕，无排版错乱、按钮错位；
3. 适配各类常用屏幕分辨率，界面展示规整统一。

### 6.3 安全需求

1. 接口请求携带身份凭证，拦截非法恶意请求；
2. 用户账号、密码等敏感信息加密传输，前端不存储隐私数据；
3. 对用户输入检索内容、评论内容做字符转义，防范脚本攻击；
4. 严格划分游客与登录用户操作权限，保障数据与系统安全。

### 6.4 可维护性需求

1. 代码遵循统一命名与排版规范，组件单一职责原则；
2. 关键业务代码、组件功能、接口调用添加详细注释；
3. 核心操作留存运行日志，便于问题排查；
4. 模块化拆分设计，支持后续功能迭代与问题快速修复。

## 七、部署与测试需求

### 7.1 部署需求

1. 项目通过Vite打包压缩优化静态资源，部署至网页服务器；
2. 配置跨域规则，保障前后端正常数据交互；
3. 划分开发、测试、正式三套环境，通过环境变量切换接口地址；
4. 服务器配置运行状态监控，定期维护、记录访问数据。

### 7.2 测试需求

1. 单元测试：对筛选、查询、展示等基础组件进行逻辑功能测试；
2. 接口测试：校验所有接口请求参数、返回数据格式与业务逻辑；
3. 功能测试：模拟真实用户全流程操作，验证所有模块功能正常可用；
4. 兼容测试：多浏览器、多尺寸设备测试页面布局与交互效果；
5. 性能测试：测评页面加载、接口请求速度，针对短板优化迭代。
